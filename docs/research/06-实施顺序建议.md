# 06 实施顺序建议

> 生成：2026-10-21 · 依据：用户拍板优先级（视觉打磨 > 城市 > 山体 > 昼夜）+ 各报告依赖关系
> 原则：每批次结束都能 `node server.js` 打开看到进步（项目「始终可运行」铁律）；每批收尾跑一次验收门。

## 批次总览

| 批次 | 内容 | 工期估 | 新增 vendor | 数据管线 | 依赖 |
|---|---|---|---|---|---|
| **B1 视觉打磨** | 水面/材质/构图/Sky/ACES | 3–4 天 | Sky.js（7KB） | 无 | 无——**今天就能开工** |
| **B2 城市** | 楼群/道路/地标/车流 | 4–5 天 | 无（InstancedMesh 是核心 API） | build-city.mjs | 无硬依赖（见软依赖注） |
| **B3 山体** | DEM 管线/地形网格/孤峰层 | 2–3 天 | 无 | build-dem.mjs | 与 B2 有一处软依赖（见下） |
| **B4 昼夜**（末位） | night 主题激活/夜窗/路灯 | 1–2 天 | （后期链可选） | 无 | B1 的 Sky/ACES + B2 的楼群 |

合计约 2–2.5 周专注开发；四批全部落地后性能预估 ≈100 dc / ≈300k tri（03 §6），预算内。

## B3 山体（与 B2 有一处软依赖）

| 步 | 事项 | 工作量 | 出处 |
|---|---|---|---|
| 3.1 | `tools/build-dem.mjs`：12 瓦片下载→解码→河道压平→Uint16 产物 | M·0.5天 | 02 §2（解码逻辑已实测跑通） |
| 3.2 | 地形网格替换地面板 + flatShading + 顶点色分层 | M·1天 | 02 §3 |
| 3.3 | 九峰独立层（×3）+ 北郊背景山群（×2）+ 标签 | S·0.5天 | 02 §4 |
| 3.4 | 断言：压平区恒 0、山体不侵河道 0.5 单位；楼群坡度抽查 | S·0.5天 | 02 §5 |

**软依赖说明**：楼群选址本应"避开坡度>15% 格点"（03 §5），但实测盆地内部起伏 <5m——**全部密集城区都在平地上**，所以 B2 先铺楼、B3 后上地形在数据上不冲突；唯一要回查的是靠近蟠龙山/鱼峰山的楼（数量个位数）。若追求零返工，可把 3.1（纯数据管线）提前到 B2 前半天跑掉。

**验收门**：河道水面无穿帮（贴花机制原样工作）；鱼峰山剪影可辨认；阴影无山脚条纹（有则调 normalBias）。

## B4 昼夜（末位，用户标注"可有可无"）

- 激活 theme.mjs night（ready:false 占位已等这一天）+ 楼群 emissive 夜窗 + 路灯/车灯 + 水面夜版参数。
- 依赖 B1 的 Sky（夜空太阳低角度）与 B2 的楼群（夜窗才有意义）。
- 若工期紧张可整批砍掉，`#btnTheme` 占位继续占位——不影响其余成果。

## 横切事项（贯穿各批次）

1. **vendor 登记**：B1 引入 Sky.js 时建 `vendor/three-examples/README.md`（05 §1 SOP），之后每加一批同步登记。
2. **文档同步**：B1 收尾时更新《原创性与知识产权说明》§3 措辞（05 §6 给了替换句）；README 的"技术实现"段随批次追加。
3. **预算哨兵**：每批收尾跑一次 draw calls/tri 实测（scene.renderer.info），写进提交信息（对齐 4.8 占位级别规范）。
4. **git 节奏**：每步一个 commit，提交信息注明占位级别与未完成项（项目既有惯例）。

# 02 山体与地形 DEM（柳州喀斯特孤峰）

> 生成：2026-10-21 · 环境：Windows 11 / node v24.13.1
> 数据来源：AWS Open Data Terrain Tiles（terrarium 编码）本机实测——12 块 z13 瓦片下载 + PNG 手写解码 + 高程采样/峰值检测全部由主会话当场运行（**[实测]**，脚本逻辑见附录 A）；Copernicus GeoTIFF 手写解析被两任代理实测证伪（**[实测-转录]**）。
> 约束对齐：风格 B（精致化风格化）——山体允许竖向夸张；山体独立层为主案；桥的 2.2 倍竖向夸张不动。

## 结论摘要

1. **terrarium 主源实测可用**：`https://s3.amazonaws.com/elevation-tiles-prod/terrarium/{z}/{x}/{y}.png`，z13（≈30m/像素）覆盖柳州需 12 块瓦片（4×3），全部 HTTP 200 [实测]；编码为标准 16bit RGB：`elev = R×256 + G + B/256 − 32768`，手写 PNG 解码（zlib + 还原滤波）一次成功。
2. **柳州"盆地+孤峰"结构被 DEM 坐实** [实测]：市中心 96–100m（平坦盆地），窗口内实测孤峰——**鱼峰山 255m、蟠龙山 176m、柳侯公园山 136m**，另有 6 座 135–223m 无名孤峰；北郊山群（233–324m）紧贴东缘可作背景层。
3. 管线：仿 build-geo 模式离线一次，产物 Uint16 高度图（128×192 ≈ 49KB raw / 66KB base64）内嵌 `app3d/terrain.mjs`；渲染 108×192 网格 ≈ **41k 三角面 + flatShading**，预算内（02 板块配额 60–100k）。
4. **竖向夸张推荐 ×3**（山体层）：鱼峰山拔地 4.8 单位（480m），与桥（≤0.7 单位）形成沙盘式主从关系；北郊背景山 ×2。
5. **最大坑：贴花水面**。地面变地形后，现有"水面/标记环 polygonOffset 贴在 y≈0"机制只在河道处继续成立——方案：**地形沿河道压平**（中心线 ±0.5 单位内强制 0，±1.5 单位内平滑过渡），v2.2 机制原样保留，山体不侵入河道。
6. Copernicus GLO-30 原始 GeoTIFF 的 float+predictor 编码手写解析不可行（两任代理实测证伪），放弃；terrarium 精度（30m）对本项目（1 单位=100m）绰绰有余。

## 2. 数据管线设计（并入 tools/，仿 build-geo 模式）

```text
tools/build-dem.mjs（离线跑一次）
  1. 下载 12 块 z13 terrarium 瓦片 → 缓存 tools/.cache/dem/（复用现有 .cache 惯例）
  2. 解码 PNG → 双线性重采样到网格：窗口 x -34..20 / z -52..44，
     采样步长 0.5 单位（50m）→ 109 × 193 格
  3. 河道压平：读 geo.mjs 河道折线，距中心线 <0.5 单位 → 强制 0；
     0.5–1.5 单位 → smoothstep 过渡到原高程（防止水面穿山帮）
  4. 基准归零：全格减去盆底基准（**注意：不能取河道采样中位数**，见下方落地修正）
     → 产物为"相对高度"，盆地≈0，鱼峰山≈+159
  5. 量化 Uint16（0..65535 映射 0..+600m，精度 1cm）→ base64
产物 app3d/terrain.mjs：export { W:109, H:193, STEP:0.5, BASE:96, data:"base64..." }
```

| 网格档 | 原始 Uint16 | base64 内嵌 | 说明 |
|---|---|---|---|
| 55×97（步长1.0） | 11KB | 15KB | 快速验证档 |
| **109×193（步长0.5）主案** | 42KB | **56KB** | 与渲染网格 1:1 |

> **落地修正（2026-10-21，已实施于 `tools/build-dem.mjs`）**
>
> 照本页原样实现会踩三个坑，实现时已改掉：
>
> 1. **压平半径必须是 1.7 / 2.6 单位，不是 0.5 / 1.5。** 江面半宽就是 1.5，
>    过渡带若从 1.5 起就开始回升，水面边缘会被江岸地形盖住，可见江面明显变窄。
>    压平区要盖满整条水面再加余量，故取 1.7；过渡带收在 2.6 是**被实测约束的**——
>    河南峰距江心 3.75、蟠龙山 4.20，再宽就会开始削这两座贴江孤峰。
> 2. **基准不能取河道采样中位数。** 本机重跑该算法得到 **64.7 m**，而非 96 m。
>    SRTM 系 DEM 在城市水面上读数系统性偏低：江心 62–70 m，两岸城区 97–100 m，差约 35 m。
>    拿江心当基准，整个盆底会被抬成 30 米台地，所有建筑与桥端埋进地形。
>    正确做法：取**距江心 > 2.6 单位的陆地点**高程中位数（实测 96.4 m）。
> 3. **网格范围要比取景窗口四周各外扩 14 单位以上**（最终取 x -48..36 / z -68..58）。
>    外圈要做 8 单位淡出斜坡与平地裙边无缝衔接，而**鱼峰山在 z=43.25，
>    距窗口南界仅 0.75 单位**——网格贴近窗口做，淡出带会正好削掉鱼峰山。
>    淡出带取 8（800 m）而非 3，是因为实测剖面证明**柳州四周都是山**：
>    z=-45 东向 7 km 外仍有 160 m 山体，北面 9 km 有 170 m、西面 7 km 有 143 m。
>    3 单位内降完 280 m 是 54°，看起来像被一刀切平；800 m 内降完 ≈ 19°，才是正常山脚。
>
> 实测结果：网格 169×253（42,757 点 / 84,672 面），产物 112 KB，
> 边界四边高度 `0.0000`、河道上方地形严格为 0、基准 96.9 m、
> 鱼峰山 4.12 单位（相对高程 137.4 m）、北郊峰 3.81 单位。
> 已知局限：50 m 网格对窄峰有采样削顶（鱼峰山 DEM 真值 255 m → 网格 234 m）；
> 36 单位以外的远山仍由平地裙边代替，背景山群按原文 B2-3.5 另做一层。
| 217×385（步长0.25） | 167KB | 223KB | 不推荐（渲染端用不上） |

浏览器端：`atob → Uint16Array`，零依赖解析；geo.mjs 同款文件头注释（来源/日期/许可）。

## 3. three.js 0.180 渲染方案

```js
// terrain.mjs（思路代码，接入 atlas.mjs）
const geo = new THREE.PlaneGeometry(54, 96, 108, 192); // 窗口 54×96 单位
geo.rotateX(-Math.PI / 2);                              // XZ 平面
const pos = geo.attributes.position;
for (let i = 0; i < pos.count; i++) {
  const gx = Math.round((pos.getX(i) + 34) / STEP);     // 窗口→格索引
  const gz = Math.round((pos.getZ(i) + 52) / STEP);
  pos.setY(i, sample(gx, gz) * EXAGGERATION);           // 相对高度 × 夸张
}
geo.computeVertexNormals();                              // flatShading 下仍需法线
const mesh = new THREE.Mesh(geo, terrainMaterial);       // vertexColors + flatShading
```

- **分辨率与三角面** [计算]：108×192 段 = 20,736 quad = **41,472 tri**（配额 60–100k ✓）。孤峰宽 300m=6 采样、岸坡过渡 4 采样——足以出剪影；不再加密（50m 以下细节在 100m/单位下不可见）。
- **flatShading 是风格的一部分**（low-poly 折面山体 + 顶点色按高程/坡度分层：岸边沙、坡面草绿、岩壁灰、山脊深绿），平滑着色反而像"没做完的写实"。
- **GROUND_Y 共存**：主案直接替换整张地面板（`buildAtlas` 中原 PlaneGeometry 地面删除）；河道压平保证原贴花机制不变。过渡期可并存（山体层浮在 0 基准上、地面板照旧），满足"始终可运行"。
- **LOD**：单 mesh 41k tri 不需要；相机 far=420 的雾已把远景吃掉大半。
- **阴影**：山体 castShadow+receiveShadow 都开；4096 阴影图（4m/纹素）下山体阴影方向正确但边缘软，可接受；flatShading 的硬折面 + normalBias 0.06 现值已覆盖 acne 风险，若山脚出现条纹优先调 normalBias 而非 bias。

### 4.2 喀斯特孤峰平原与夸张档位

柳州是教科书级**喀斯特孤峰平原**：盆底平坦（实测 <5m 起伏），孤峰拔地而起、沿江贴城（蟠龙山几乎悬在江边）。真实比例下鱼峰山相对盆底 160m ≈ 1.6 单位——在 5.4×9.6km 的取景里只是"小土包"，这是"真实但不上镜"的典型。

| 档位 | 倍率 | 鱼峰山视觉高度 | 效果 | 建议 |
|---|---|---|---|---|
| 等比 | ×1 | 1.6 单位 | 地图正确、观感平淡 | 对照组 |
| **主案：局部夸张** | **×3** | **4.8 单位** | 沙盘模型感，孤峰成为构图主角，与桥（0.3–0.7 单位）形成 10:1 主从 | ✅ 采用 |
| 更强 | ×4–5 | 6.4–8.0 单位 | 国风立轴感，但压过桥梁主体 | 试渲染后定，默认不用 |

- 结构件 2.2 倍**不动**（v1.5 的取舍声明仍然成立）；山体层独立倍率（×3/背景 ×2），两层各自内部一致即可，不存在物理正确性约束；
- 山体不参与"桥在河上"等地理断言的基准面；新增断言：河道压平区高程恒为 0、山体格点不落在河道中心线 0.5 单位内。

## 5. 性能与坑

1. **贴花水面适配（最重要）**：水面/标记环/河道各层都是 y≈0 的 polygonOffset 贴花（v2.2）。地形只在河道压平区与它们共面，压平区外贴花不存在（河本来就在那里）→ 机制零改动。**风险点**：压平过渡带的坡面上若误放码头/标记环会半嵌入坡体——标记环生成逻辑加"距河道中心线 <1.2 单位"约束（它们本来就该在河上）。
2. **楼群/道路联动**（03 报告）：楼群 footfall 避开坡度 >15% 的格点（管线里查地形表）；滨江路在压平带内天然 y=0。
3. **flatShading + 阴影**：见 §3；山脚条纹优先调 normalBias。
4. **体积**：产物 56KB base64（主案档），加载瞬时；渲染 41k tri，draw call 1 个（单材质单 mesh + 顶点色）。
5. **断网/降级**：terrain.mjs 是纯数据模块，与 WebGL 无关；`#browse` 不受影响。

## 1. 项目快照

- **名称**：桥见柳州——面向青少年的柳州城市桥梁科普 3D 网页（参赛作品）
- **形态**：打开即单一 3D 柳江总览场景（atlas），规划四态（atlas / bridge / lab / archive）+ browse 降级
- **技术栈**：原生 JS ES modules（.mjs）+ Three.js 0.180.0（`vendor/three/`，仅 three.module.min.js + three.core.min.js，**无 examples/jsm**）
- **零 npm 依赖、零构建**；`node server.js` 静态服务（MIME 已含 .mjs/.glb/.bin/.hdr 等）；完全离线
- **代码规模**：app3d/ 9 模块约 2,720 行；app.js（2D 版）1,587 行保留为降级子视图
- **地理数据**：`app3d/geo.mjs`（产物，勿手改）——OSM 实测河道 + 五桥真实桥位/桥轴/桥长/桥宽（ODbL，页面已署名）；离线管线 `tools/build-geo.mjs`，原始响应缓存 `tools/.cache/`
- **权威现状文档**：`docs/3D重构开发计划.md`（v1.0–v2.2 变更记录即全项目踩坑史）

## 5. 关键踩坑史（新功能必须绕开）

1. **file:// 不可用**——ESM/fetch/纹理全挂，必须 HTTP 访问（M0）。
2. **vendor 要带全依赖闭包**——three 0.180 的 three.module.min.js 内部还 import three.core.min.js，M0 只拷主文件导致 3D 必挂。vendor examples 模块同理：先查 import 链。
3. **改相机逻辑先查钳制链**——v1.5 发现 focusOn 把距离钳到 60，"拉近到 9"从未生效。
4. **提亮要整体联动**——v1.8 的"一片黑"修复涉及天空/雾色/地面外边/环境反射联动；单改灯没用。
5. **z-fighting 三连教训**（v1.9–v2.2）：near 平面吃深度精度 → 层间距统一 0.04 步进 + polygonOffset 贴花化；大面积重叠装饰带直接删除而非调参。**山体起伏会破坏现有贴花前提**——水面/标记环目前贴在 y≈0 平面上，地面变地形后必须适配（见 02 报告）。
6. **地面是一整张连续平面，低于它的东西会被盖住**（v2.2 结论）——山体不能走"局部挖洞"，要么整体替换地面，要么山体独立成层。
7. **河道必须单条连续折线、端点在画外**（v1.7 回归断言）——任何新数据管线照此模式加回归断言。
8. 原"沙箱禁 Chromium"限制仅针对当时的开发环境；用户本机可直接开浏览器做视觉验证。

## 7. 验证纪律（沿用项目既有做法）

- `node --check` 所有改动模块；
- 几何自检断言（"桥在河上、建筑在陆地"式的地理正确性断言）——山体/楼群加同类断言（如：孤峰位置与 DEM 高程一致、楼群不落在河道内）；

- 视觉效果最终需人工打开浏览器确认。

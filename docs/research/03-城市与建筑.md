# 03 城市与建筑（OSM 数据 × 大规模渲染）

> 生成：2026-10-21 · 环境：Windows 11 / node v24.13.1
> 数据来源：Overpass API 实测（原始响应存 `$LOCALAPPDATA/Temp/liuzhou-*.json|csv`，统计由主会话复算 [实测]）；地标坐标与楼高来自调研转录 [实测-转录]；投影公式照抄 `tools/build-geo.mjs` 的 `project()`（等距投影，原点 24.342,109.420，1 单位=100m）。
> 约束对齐：性能预算 ≤300 draw calls / ≤400k 三角面（暂定）；vendor three MIT 模块已许可（见 05 报告）。

## 结论摘要

1. OSM 城市数据覆盖充足：bbox 内 **2799 栋建筑、3276 条道路（1246.7km）、932 块用地、174 个 POI** [实测]。
2. **真实楼高稀缺是最大限制**：带 height 标签的仅 6 栋（恰好都是地标超高层）、带 building:levels 的 46 栋（1.6%）[实测]——楼高必须程序化推算，地标楼用实测真值。
3. 建筑渲染主案 **InstancedMesh**（单位盒 + 逐实例变换/颜色，零 vendor）；BufferGeometryUtils 合并方案备选（35.5KB，仅依赖 'three' [实测-转录]）。
4. 道路渲染**可直接复用** `geometry.mjs` 的河道「折线→条带」管线 [实测]——道路就是"更多、更细、分级配色"的河道；按等级合并成 ≤8 个 draw call。
5. 城市数据管线并入 `tools/build-geo.mjs`：产物为楼群表（中心/尺寸/旋转/类型/高度）+ 道路折线表（简化后），浏览器端生成 InstancedMesh/条带。
6. 六座真实摩天楼中五座在取景窗口内（地王国际财富中心 311m 为最高），值得单独建模；其余 2700+ 栋全部程序化推算高度。

## 1. OSM 城市数据覆盖度 [实测]

查询范围 bbox (24.30, 109.36, 24.38, 109.50)（比取景窗口略大），overpass-api.de 直连可用（本机实测 0.9s/请求）。原始数据四份：`liuzhou-buildings.csv`（60KB）、`liuzhou-highways.json`（2.0MB，含 geometry）、`liuzhou-landuse.json`（230KB）、`liuzhou-pois.json`（38KB）。

### 1.1 建筑

| 项 | 值 |
|---|---|
| 建筑 way 总数 | **2799** |
| 带 `height` | **6**（即 1.1 节的六座地标楼，覆盖率 0.2%） |
| 带 `building:levels` | **46**（1.6%；按 3m/层换算高度） |
| 类型分布（前 8） | yes 1765 / apartments 653 / commercial 99 / industrial 64 / school 61 / dormitory 21 / residential 33 / office 20 |

**推论**：93% 的楼无任何高度信息（`yes`/`apartments` 占绝对多数）→ 高度走类型启发式：apartments/residential 3–7 层（9–21m）、commercial/office 2–9 层、industrial/warehouse 1–2 层大跨度、school 3–5 层；46 栋有 levels 的用真值；6 栋地标用 height 真值。伪随机抖动避免"整城一样高"。

### 1.2 道路

| 项 | 值 |
|---|---|
| way 总数 / 折线带 ≥2 点在窗口内 | 3276 / **2003** |
| 总里程 / 窗口相关里程¹ | 1246.7 km / ≤661.9 km |
| 分级里程（窗口相关，前 10） | tertiary 195.7 / service 194.4 / residential 191.2 / secondary 186.3 / primary 123.5 / trunk 96.1 / cycleway 70.0 / footway 46.1 / unclassified 30.3 / primary_link 24.3 (km) |

¹ 统计口径：≥2 点落入窗口的折线全长（上界估计），实际在窗口内部分略小。

**分级取用建议**：trunk + primary + secondary + tertiary + residential 五级入景（≈790km 相关里程、1500 条）；service/footway/cycleway 降采样或舍弃（画出来是噪点）。geometry 里已带每折线坐标序列（含共享节点重复，可直接投影）。

### 1.3 用地与 POI

- landuse 932 块（窗口内完全包含 613）：residential 589 / commercial 62 / industrial 55 / construction 47 / grass 41 / retail 14 / brownfield 12 / railway 11 / military 5 [实测]。**用途**：给楼群分区配色（住宅区暖灰、商业区亮、工业区冷）、绿地优先留空不盖楼。
- POI 174 个：ferry_terminal **21**（柳江轮渡码头，滨水特色，值得在滨江路做 2–3 处码头小景）/ viewpoint 14 / artwork 9 / museum 4 / attraction 3 / theatre 1 [实测]。

## 3. 大规模建筑渲染（three 0.180）

### 3.1 两方案对比

| 方案 | 原理 | draw calls | 顶点负担 | 灵活性 | 结论 |
|---|---|---|---|---|---|
| **InstancedMesh（主案）** | 单位 1×1×1 盒，实例矩阵给 (cx, 0, cz)+scale(w,h,d)，`setColorAt` 逐实例颜色 | **每材质 1 个**（≈3–5 个） | GPU 实例化，CPU 侧零重复 | 加/删楼=改实例数；高度动画易 | ✅ 主案 |
| 合并 BufferGeometry | `mergeGeometries` 把每栋盒烘成一个网格 | 1–2 | 同量级 | 静态；改楼要重建 | 备选（同风格"永不增删"时再考虑） |

- InstancedMesh 不需要 vendor 任何模块（three 核心 API）；BufferGeometryUtils 若日后需要（合并道路/非盒体异形楼）再 vendor，35,539B、只 import 'three' [实测-转录]。
- **阴影注意**：InstancedMesh castShadow 正常工作；2000+ 栋全投影会加大 4096 阴影图负担（现有 155 投影网格的量级说明可行，但楼高影长，建议只让 h>30m 的楼投影）。

### 3.2 顶点/预算表（窗口内楼群按 ~1800 栋估）

| 方案 | 实例/顶点 | 三角面 | draw calls |
|---|---|---|---|
| 全部单盒 | 1800 实例 × 24 顶点 | 1800×12 = **21.6k** | 1–3 |
| 30% 加坡顶（+三棱柱） | +540×12 顶点 | +6.5k → **28k** | +1 |
| 地标 2 栋精细（退台+竖纹） | ~2k 顶点/栋 | ~4k | 2–4 |
| **合计** | — | **≈32k** | **≤8** |

### 3.3 屋顶与立面细节（低面数手法）

- **女儿墙**：盒顶加 0.3m 檐口圈——不做（三角面×2 不值），用屋顶颜色差（顶面深一档）表达；
- **坡顶**：住宅楼 30% 概率三棱柱帽（12 tri）；
- **退台**：地标楼 2–3 段堆叠盒；
- **窗户贴图（程序化 canvas，白天/夜晚两版）**：512² 画布画窗格网（亮窗米白/暗窗深灰随机），`map.repeat` 按楼高设置（`h/3m` 层 × 每层 4 窗），UV 用 `worldscale` 思路避免拉伸；夜晚版改 emissiveMap（随机 40% 亮窗、色温 #ffcf9a），切换主题时换 `emissiveIntensity`。同一张贴图全城共用（省内存）。

### 3.4 高度合成算法（管线内完成）

```text
height(b) =
  b.height                          ? 有 height 标签（6 栋）
  : b.levels ? levels × 3m          ? 有 levels（46 栋）
  : typeBase[type] × jitter(0.8–1.3)  其余
typeBase: apartments/residential 4层, commercial 3, office 5, school 4,
          industrial 1.5(大跨度), dormitory 5, hotel 6, hospital 5
```

jitter 用 id 做种（确定性，与项目现有伪随机规范一致）。

## 4. 道路系统

**结论：直接复用 `geometry.mjs` 管线 [实测]**——它就是"折线→等宽条带网格"（河道同款原语），道路只需：分级宽度（trunk 0.22 单位=22m / primary 0.16 / secondary 0.12 / tertiary 0.09 / residential 0.06）+ 分级材质色（沥青 #3a3d42，主干道加中线色带可用第二张窄条带或顶点色）。

- **贴花 vs 抬升**：沿用现有贴花路线（polygonOffset，v2.2 已验证的机制）——地面维持 GROUND_Y=0 平面时零风险；若 02 报告的地形在河岸处抬升，滨江路一段随地形抬升（数据管线里按道路点到河岸距离给 z 偏移即可）；
- **性能**：按等级合并——每级一条 merged 条带（BufferGeometryUtils 或手写合并），5 级 = **5 draw calls**，~790km× 平均 6 段/条 ≈ 46k 三角面（每段 2 tri/m，可再简化到 25k）；
- **滨江路**：沿江一侧的 primary（数据里可按"平行河岸<200m"筛出）加 0.5 单位宽浅色带 + 路灯点精灵，是"桥见柳州"构图里江岸轮廓线的一部分；
- 折线简化：Douglas–Peucker(8m) 已是项目成熟工艺（build-geo.mjs 河道同款），道路照抄。

## 7. 数据管线设计（并入 tools/build-geo.mjs）

```text
Overpass（bbox 查询，四类一次跑）
  ├─ buildings ──► 高度合成（§3.4）──► 楼群表 buildings.json
  │     字段: {id, cx, cz, w, d, rot, h, type, accent}（投影到项目坐标， footprint 用 bounds 对角线估 w/d/rot）
  ├─ highways ───► DP(8m) 简化 + 分级过滤 ──► roads.json
  │     字段: {class, width, pts:[[x,z]...]}
  ├─ landuse ────► 绿地/水域面（楼群避让层）──► zones.json
  └─ pois ───────► 码头/景点锚点 ──► pois.json
产物体积估算: buildings ~1800×60B ≈ 110KB（可 Float32 二进制化到 ~50KB）
浏览器端: geo-city.mjs 导入表 → atlas.mjs 建 InstancedMesh / 合并条带
```

**回归断言**（照项目惯例）：楼群全部在陆地（到河道中心线距离 > 河宽/2 + 楼半宽）；道路折线端点不出窗口；地标楼高与真值一致；产物体积上限告警。

# 安全提示与签名说明

> 面向：评委、机房老师、第一次运行作品的人。
> 结论先说：**会遇到系统提示是正常的**——两个 exe 都没有数字签名证书，这一点在下面逐条解释，并给出三种消除办法。

## 一、你会看到哪三种提示

| 提示 | 触发条件 | 与签名的关系 |
|---|---|---|
| UAC 里的发布者显示 **「未知发布者」** | 程序需要管理员权限时（本作品只有点「放行防火墙」时才会） | 直接原因：**没有 Authenticode 代码签名证书** |
| **「Windows 已保护你的电脑」**（SmartScreen，带「更多信息 → 仍要运行」） | 文件带「来自网络」标记（从 GitHub/ZIP/邮件拿到的），且该文件没有信誉积累 | 间接原因：未签名 ⇒ 无发布者信誉 ⇒ 新文件一律先拦 |
| 属性里的 **「此文件来自其他计算机，可能被阻止」** | 文件被 Windows 打上 `Zone.Identifier` 备用数据流 | 与签名无关，纯粹是「下载来的文件」标记 |
| Defender 提示「正在修改防火墙规则」 | 点「放行防火墙」按钮时（自身行为，非病毒） | 与签名无关；未签名程序更容易被行为监控盯上 |

本机实测（2026-10-23）：

```
桥见柳州.exe             NotSigned   发布者：无   Zone.Identifier：无
桥见柳州-手机访问.exe      NotSigned   发布者：无   Zone.Identifier：无
```

也就是说：**从本仓库自行编译出来的 exe 不会被 MOTW 标记**，只有在「下载别人的 ZIP / 从网页另存」时才会带上那两种「来自网络」的提示。

## 二、安全地继续运行（推荐给评委）

1. 确认文件来源是本仓库（或随作品提交的 U 盘），核对下面的 SHA-256；
2. 如果是下载来的 ZIP，先解除锁定：

   ```powershell
   Get-ChildItem *.exe | Unblock-File
   ```

3. 出现「Windows 已保护你的电脑」时：点「更多信息」→「仍要运行」；
4. 只有点「放行防火墙」时才需要同意 UAC（启动本身不申请任何权限）。

### 校验值

| 文件 | 大小 | SHA-256 |
|---|---|---|
| `桥见柳州.exe` | 20480 字节 | `7ee6c32fdc173cbdef506f77133815dc3028ad242ad6067221c5b43819c09055` |
| `桥见柳州-手机访问.exe` | 19456 字节 | `834bfac31102f559f143f7f2364540f38d1cd62ff3a00cdb96f3e075e68932d3` |

每次重新编译后校验值都会变，请以当次产物为准：

```powershell
Get-FileHash 桥见柳州.exe -Algorithm SHA256
```

## 三、彻底消除提示的三种办法

### 办法 A：让程序在目标机器上就地编译（零成本，推荐用于评审）

仓库里带源码，Windows 自带 .NET Framework 的 `csc.exe`，一条命令即可生成**全新、无「来自网络」标记**的可执行文件：

```powershell
node tools/build-launcher.mjs
```

本地编译出来的文件没有 `Zone.Identifier`，SmartScreen 通常不会介入。这条路径同时向评委证明「可执行文件由随附源码直接产生」，可复现性最强。

若机器连 Node.js 都没有，也可以直接用 `python -m http.server 4173` 或任意静态服务器打开作品——**exe 只是打包了同一套静态文件的便利入口**，不是必需品。

### 办法 B：购买代码签名证书（一劳永逸，有成本）

| 方案 | 大致成本 | 效果 |
|---|---|---|
| OV（组织验证）代码签名证书 | 约 ¥1000–3000 / 年 | UAC 显示真实发布者；SmartScreen 信誉需要时间与下载量积累 |
| EV（扩展验证）代码签名证书 | 约 ¥3000–6000 / 年 | **立即**获得 SmartScreen 信誉，通常不再出现「已保护你的电脑」 |
| Azure Trusted Signing | 约 $9.99 / 月 | 微软托管签名，信誉建立较快，适合长期分发 |
| SignPath.io（开源项目免费） | 免费（需审核） | 适合开源仓库；审核通过后可自动化签名 |

### 办法 C：向微软提交误报 / 白名单申请

如果 Defender 报的是行为拦截（而不是 SmartScreen 信誉问题），可以提交样本由微软复核：

<https://www.microsoft.com/en-us/wdsi/filesubmission>

提交时说明：程序是本地静态网站启动器，仅监听本机/局域网端口，仅在用户点击按钮后才通过 `netsh` 添加一条入站规则，可与 `launcher/Program.cs` 源码一一对应。

## 四、作品在「少触发系统提示」上已经做的设计

| 设计 | 目的 |
|---|---|
| **启动阶段不申请管理员权限** | 双击不会弹 UAC；只有点「放行防火墙」才提权一次 |
| 提权只执行 `--add-firewall-only`，只做两件事：加一条程序入站规则、加一条端口规则 | 行为可审计，不写注册表、不驻留服务 |
| 程序只读项目目录内的文件，拒绝目录穿越 | 不能读系统或其他目录 |
| 不联网（除被启动的浏览器访问本机地址） | 无外连行为 |
| 关闭窗口即退出，不常驻 | 无后台进程 |
| 局域网版可在地址窗口点「停止服务」随时断开 | 开放范围可控 |

## 五、常见疑问

**Q：为什么不是「未知发布者」就是「已保护你的电脑」？**
A：前者是 UAC 对「没有签名」的表述；后者是 SmartScreen 对「没有信誉」的表述。签了名（OV）能改善前者，只有 EV 或长期信誉才能改善后者。

**Q：自签名证书行不行？**
A：不行。自签名不被系统信任，UAC 依旧显示「未知发布者」，SmartScreen 也不会因此放行。

**Q：不改任何设置，怎么最稳地演示？**
A：在演示机上先跑一次 `node tools/build-launcher.mjs`（或直接用 `node server.js` + 浏览器），此后所有提示都不会出现。
